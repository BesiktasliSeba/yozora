# text

## stack

- freetype 2.15.0 with zlib, brotli and libpng, so site fonts in ttf, otf, woff and woff2 load and color bitmap fonts draw
- harfbuzz 14.6.0 for shaping
- icu 78.3 for segmentation, bidi, normalization and collation, built into the binary with its data
- skia draws the glyphs, the font manager is `FontManagerYozora.cpp`

## fonts

fonts come from an owned catalog shipped in the app, not from the system, so a page looks the same on every system version. fallback fonts are generated by `tools/make_fallback_fonts.py`. the interface uses Roboto and, in the log screen, JetBrains Mono registered through `UIAppFonts` so pages never see it.

a font file that a page sends is checked and loaded, a woff2 goes through brotli. `scripts/check_text_woff2.sh` refuses a freetype that was built without it.

## emoji

the family `Apple Color Emoji` is a generated cbdt font, with png strikes of the same pictures the interface uses (56 pixels, 3963 pictures, 3835 sequences through `ccmp`: zwj, flags, keycaps, skin tones). webcore asks for it when a cluster is emoji, so a text symbol without the emoji selector stays a glyph of Roboto, and the font manager skips the family in the generic fallback loop.

- the font is not committed, see [build](build.md) for how it is made
- it is read whole into memory at start, 9.5 MB

## test

`tests/test_emoji_font.py` shapes the font with freetype and harfbuzz on the host. `meow build text-host` builds the text stack.
